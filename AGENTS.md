# Commonstar working agreement

## Source of truth

Read README.md, STATUS.md and the portions of SPECIFICATION.md relevant to the requested change. This repository is the Commonstar project; unrelated operating-system and memory repositories are independent. The latest user instruction supersedes an older design decision, and a consequential change must be recorded.

Use one main implementation lane and at most one repair/review lane unless work is genuinely independent. Confirm repository owner, branch, current implementation and nearest instructions before external writes. Keep changes reviewable and preserve unrelated work.

## Product invariants

- A complete local tutor and organizer is required. Do not replace it with a remote-only chat client.
- The learner device owns identity, authoritative memory, retrieval, policy and validated writes.
- Model output is untrusted. No model-created permissions, teacher signatures, official grades or unrestricted shell/SQL tools.
- Remote inference is explicit and minimized. Never silently send personal data or enable paid cloud use because local generation is slow.
- Models reference request-scoped sources/evidence; local code maps those to stable records.
- Every private derivative is inside the protection and retention design: extracted text, vectors, thumbnails, logs and caches included.
- One encrypted backup destination is versioned and restore-tested. No unmentioned cloud synchronization.
- Public source contains synthetic fixtures only. Keep real vaults, credentials, recovery material and sensitive screenshots outside the checkout.

## Completion evidence

Finish the authorized user path through persistence, errors, recovery and verification. Passing schema tests does not establish an implemented app. A package build does not establish a bootable ISO. An adult demo does not establish child suitability or educational gains.

Record exact source/runtime/model identities and what ran in verification/. Do not weaken tests to obtain a passing result. Hardware, accessibility, provider calls and learning outcomes require their own evidence.

For changed UI, inspect the actual desktop and narrow-window interface, keyboard/screen-reader behavior, loading/empty/error/recovery states and reduced motion. For installation changes, test boot, encryption, restart and recovery on an expendable target before a physical user install.

## Release and permissions

Model and content downloads must use pinned identities, verify actual bytes and preserve licenses. Current model catalog hashes are upstream observations until independently checked. Runtime source-read pins are not compiled/model-tested release locks.

Do not create a paid service, spend money, expose a workstation publicly, send outreach, upload a real learner record, overwrite a disk or claim an institutional endorsement without the required scoped authorization. Public project publication was requested; unrelated private work is not included in that permission.

Update STATUS.md after meaningful changes with actual checks and blockers. Keep unresolved device or provider prerequisites precise and actionable.
